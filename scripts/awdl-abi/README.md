# AWDL experimental ABI reconstruction — macOS 26.7.2 (25G332)

This directory contains a **standalone** reconstruction of the kernel-side
`IO80211AWDLProtocol` hierarchy for the running build, plus a compile/link
harness. Nothing here is wired into the AirportItlwm target, nothing is
installed, and no AWDL interface is allocated.

### Stage 1.5: the 63 AWDL slot identities

The pure AWDL slots have no symbol of their own, but the concrete subclass
does. `AppleBCMWLANProximityInterface : IO80211AWDLProtocol` has its own
`__ZTV` at `0xffffff80017f9b68` (574 entries), and it overrides slots
505–567 with **63 distinct functions**. Each override's mangled name carries
both the method name and the parameter type:

```
slot 505 -> __ZN30AppleBCMWLANProximityInterface7getSSIDEP20apple80211_ssid_data
slot 538 -> __ZN30AppleBCMWLANProximityInterface13setAWDL_BSSIDEP21apple80211_awdl_bssid
slot 567 -> __ZN30AppleBCMWLANProximityInterface29setAWDL_RTG_PEER_STATS_CONFIGEP29apple80211_rtg_peer_stats_cfg
```

Independent cross-check: the global `apple80211get*` / `apple80211set*`
bridges in `IO80211Family` `safeMetaCast` to `IO80211AWDLProtocol` and then
tail-jump through the same vtable offset. All 63 slots are reached this way,
for example:

```
apple80211getSSID   -> [vptr + 0xfc8] -> slot 505
apple80211setAWDL_BSSID -> [vptr + 0x10d0] -> slot 538
apple80211setP2P_COEX_PROTECTION -> [vptr + 0x11a0] -> slot 564
```

Return convention: all 63 overrides write a 32-bit value to `eax` before
`ret` (9 return `xor eax,eax`, 47 return a register, 7 return an immediate
error constant). None returns a pointer in `rax` or a float in `xmm0`. The
bridges forward that value unchanged as their own `IOReturn`, so the
`IOReturn` declarations are ABI-safe.

`verify_slots_kc.py` performs all of the above and compares the result with
the header declarations. It currently reports **63/63 verified**, with zero
name, parameter-type or return-convention mismatches.

The three slots after the AWDL block belong to the Proxi subclass, not to
`IO80211AWDLProtocol`, and are deliberately not modelled:

| Proxi slot | Method |
|---|---|
| 568 | `getTX_RATE(apple80211_tx_rate*)` |
| 569 | `init(AppleBCMWLANCore*, ether_addr*, unsigned int, char*)` |
| 570 | `freeResources()` |

### FlowQueueHash correction

The KC mangles `IO80211FlowQueueHash` as an **enum**:

```
__ZN23IO80211VirtualInterface21findExistingFlowQueueE20IO80211FlowQueueHash
```

The legacy header `include/Airport/IO80211VirtualInterface.h` typedefs it as
`UInt64`. Do not mix that header with these experimental headers; the
by-value ABI differs.

## Stage 2: concrete class (not instantiated)

`AirportItlwm/AirportItlwmAWDLInterface.hpp` and `.cpp` add a concrete
`IO80211AWDLProtocol` subclass for ABI bring-up. It is compiled into the Tahoe
target, but it is **never allocated, attached, registered, started or
advertised**. `setVIRTUAL_IF_CREATE` remains fail-closed and is not wired to
the class.

The class follows the 25G332 layout rules:

- derives only from the experimental `IO80211AWDLProtocol`;
- adds no data members (`sizeof` stays `0x130`);
- adds no new virtual methods (vtable stays 571 entries);
- overrides only slot 488 (`setMacAddress`) and the 63 AWDL slots 505..567;
- every override is a fail-closed `kIOReturnUnsupported` stub;
- the whole translation unit is guarded by `ITLWM_AWDL_EXPERIMENTAL`.

`itlwm.xcodeproj` adds only `AirportItlwmAWDLInterface.cpp` to the
`AirportItlwm-Tahoe` Sources phase. No other target builds it.

## Stage 3: lifecycle skeleton (registration still closed)

Stage 3 adds non-virtual lifecycle methods to the same class. They add no
data members and no virtual methods, so the vtable stays at 571 entries and
the instance size stays `0x130`.

```c
bool initLifecycle(IO80211Controller *owner, const ether_addr &mac);
IOReturn startLifecycle();
IOReturn stopLifecycle();
void teardownLifecycle();
bool isLifecycleInitialized() const;
bool isLifecycleRunning() const;
bool buildRegistrationInfo(void *buffer, size_t size) const;
```

Because the class cannot gain ivars, state lives in a fixed, module-local
side table keyed by object address:

| Property | Value |
|---|---|
| records | 8, keyed by `AirportItlwmAWDLInterface *` |
| lock | one lazily allocated `IOLock`, raced with `OSCompareAndSwapPtr` |
| owner | weak `IO80211Controller *` (no retain cycle) |
| states | `Empty`, `Initialized`, `Starting`, `Prepared`, `Running`, `Stopping`, `TornDown` |
| start accounting | `startCount`; nested successful starts are reference-counted |

Semantics:

- `initLifecycle()` rejects a second init on the same object and claims a
  record only on success.
- `startLifecycle()` requires `Initialized`, checks the runtime boot-arg
  gate, builds and validates a local `0x130`-byte `RegistrationInfo`, moves to
  `Prepared`, then **returns `kIOReturnUnsupported` and rolls back to
  `Initialized`**. No pool, queue, registration or retain survives.
- `stopLifecycle()` is idempotent in `Initialized`/`TornDown`, rejects
  in-flight transitions with `kIOReturnBusy`, and reference-counts
  `Running`.
- `teardownLifecycle()` clears the owner/MAC and frees the side-table slot
  exactly once; double teardown is a no-op.

`buildRegistrationInfo()` writes the KC-derived values (version `1`, size
`0x130`, family `2`, `maxSize 0x100`, reserved `0x22`, initial media `0x20`,
min packet size `0x2e`, headroom `0`, both MTU fields `0x594` = 1428, BSD
prefix `"awdl"`) and the six MAC bytes at `+0x108`, after rejecting an all-zero
or multicast MAC. Stage 4 corrected the earlier Stage 3 fallbacks after
re-reading `AppleBCMWLANProximityInterface::start()` and `getBSDNamePrefix()`;
see `STAGE4_BUILD_REPORT.md`.

### Registration gate

`ITLWM_AWDL_REGISTRATION_ENABLED` defaults to `0`, and a `static_assert`
rejects building with `1`. `startLifecycle()` cannot reach `Running`; no code
path returns success from a start. The class imports no
`registerEthernetInterface`, `initRegistrationInfo`,
`deregisterEthernetInterface`, `IOSkywalkPacketBufferPool` or
`IOSkywalkQueueSet` symbol, and `verify_awdl_class.py` enforces that.

`STAGE3_BUILD_REPORT.md` lists the conditions required before registration
can be enabled: real base init, TX/RX pools, queues, a complete
`RegistrationInfo`, link state, sync/channel setup, reviewed start/stop
ordering, rollback, locking/lifetime, the runtime gate, a KC drift check and
explicit review.

## Stage 4: datapath resource manager (still not wired)

Stage 4 adds a separate, non-IOKit manager in
`AirportItlwm/AirportItlwmAWDLDatapath.{hpp,cpp}`. It is not an ivar and not a
virtual of the AWDL class, so the verified `0x130` size and 571-entry vtable
are unchanged.

The manager owns exactly five resources in a fixed order:

```
TX pool -> RX pool -> TX submission queue -> TX completion queue -> RX completion queue
```

Teardown and every failure rollback run in reverse:

```
RX completion -> TX completion -> TX submission -> RX pool -> TX pool
```

| Property | Value |
|---|---|
| states | `Idle`, `Allocating`, `Ready`, `TearingDown`, `TornDown`, `Failed` |
| resources | 5 slots, all non-null before `Ready` |
| minimum queue capacities | TX submission `8`, TX completion `2`, RX completion `2` (from KC) |
| `PoolOptions` | `0x20` bytes, offsets pinned by `static_assert` |
| packet entry points | `transmit()`/`receive()` always zero the count and return `kUnsupported` when `Ready` |
| live gate | `ITLWM_AWDL_DATAPATH_LIVE` defaults to `0`; the backend create methods return NULL |
| registration gate | `ITLWM_AWDL_REGISTRATION_ENABLED` stays `0`; the AWDL class does not include the manager |

The real backend declares the four 25G332 factory symbols by their exact
mangled names, because the SDK callback typedefs use `IOReturn` (`int`) while
the KC mangles the callback return as `unsigned int` (`j`). The backend object
imports exactly those four Skywalk symbols plus `operator new/delete`; it
imports no registration, attach or enable entry point.

Host tests (`scripts/awdl-abi/test_datapath.cpp`) use a fake backend and cover
initial state, success/teardown, double init, double teardown, all five
rollback steps, invalid configs, fail-closed packet paths and the exactly-once
packet ledger.

```sh
  --kext /tmp/awdl-experimental/Release/Tahoe/AirportItlwm.kext \
  --default-kext /tmp/awdl-default/Release/Tahoe/AirportItlwm.kext
```

## Remaining unverified

- **Return types of inherited virtual methods.** Itanium mangled names do not
  encode return types. The 63 AWDL overrides are known to write a 32-bit
  `IOReturn`-sized value in `eax`, but the exact source-level type is not
  encoded. The inherited VIF/Skywalk declarations (including `enable`,
  `disable`, `initBSDInterfaceParameters`, `setMacAddress`, and the 27 VIF
  methods) use the reference-derived `uintptr_t`/`bool` types. The Stage 2
  class follows those declarations exactly; a wrong inherited return type
  would be an ABI mismatch that the compiler cannot catch.
- **Payload struct layouts.** Only the pointer types are proven. The fields of
  `apple80211_*` are not checked against the 25G332 KC; the driver must not
  dereference them until they are. The Stage 2 stubs do not touch them.
- **Runtime lifecycle.** The class is a compile/link artifact. Its IOKit
  metaclass is registered when an experimental kext loads (normal
  `OSDefineMetaClassAndStructors` behaviour), but no instance is allocated and
  no IO80211 interface is registered. Stage 3 tracks owner, MAC and start/stop
  state in a side table, but `startLifecycle()` always fails closed. Attaching
  it later would still require a reviewed allocation, channel/sync setup, and
  a real start/teardown path.
- **Layout drift.** The vtable and instance-size checks are tied to 25G332.
  A future kernel collection that changes the AWDL vtable would invalidate the
  experimental headers and this class together.
- **Method semantics.** The KC proves which function occupies each slot, not
  what a driver should do there.
- **Exact error constants.** Several overrides return method-specific codes
  (for example `0x66`, `0x8`, `0x10`, `0xe0000001`, `0xe00002bc`). The header
  commits only to the `IOReturn` register/width.
- **Proxi-only slots 568–570** (`getTX_RATE`, `init`, `freeResources`) are not
  part of `IO80211AWDLProtocol` and are deliberately not modelled.

## Deliberately not done

- Only `AirportItlwmAWDLInterface.hpp/.cpp` include the experimental AWDL
  header; no other driver source does.
- No `IO80211AWDLProtocol` subclass is instantiated, attached, registered or
  started.
- The Stage 3 lifecycle is not enabled: `startLifecycle()` always returns
  `kIOReturnUnsupported`, `Running` is unreachable, and
  `ITLWM_AWDL_REGISTRATION_ENABLED` is fixed at `0` by a `static_assert`.
- The Stage 4 datapath manager is compiled only in the experimental build and
  is not referenced by the AWDL class, `setVIRTUAL_IF_CREATE`, the controller
  or any hardware path. `ITLWM_AWDL_DATAPATH_LIVE` is fixed at `0` by a
  `static_assert`, so even an accidental call cannot allocate a pool or queue.
- The class is not connected to `setVIRTUAL_IF_CREATE`, and no AWDL capability
  is advertised.
- No AWDL interface is allocated, registered or published.
- Stage 1's `setVIRTUAL_IF_CREATE` remains fail-closed
  (`kIOReturnUnsupported`, no `bsd_name` write, no `awdl0`).
- No kext installed, no EFI/SIP changes, no reboot.

## Next step

Stages 2, 3 and 4 are complete: the 25G332 vtable layout, instance size, all 64
method symbols, the lifecycle skeleton and an isolated datapath resource
manager are reproduced and link strictly against the local KC. The remaining
work is behavioural and payload-level, not slot discovery:

1. Verify the `apple80211_*` payload struct layouts against the 25G332 SDK/KC
   before any method dereferences a pointer.
2. Decide which of the 63 stubs can safely return real data (read-only
   getters) and which must stay unsupported.
3. Choose real `PoolOptions` values and queue IDs from the controller, then
   wire the Stage 4 manager into a reviewed start/stop path. Do not flip
   `ITLWM_AWDL_DATAPATH_LIVE` until that wiring, the owner lifetime, the
   callback contract and the packet ledger are reviewed together.
4. Implement the registration path listed in `STAGE3_BUILD_REPORT.md`: base
   init, a complete `RegistrationInfo`, link state, sync/channel setup, and
   start/stop ordering with rollback.
5. Keep `setVIRTUAL_IF_CREATE` fail-closed until that path has been reviewed
   and the runtime gate is deliberately armed.
6. Only then consider allocating or advertising an AWDL interface.


## Stage 4.2 — callback admission safety (experimental, no runtime activation)

The Stage 4.2 review branch adds an atomic, initially disarmed `CallbackGate`
and an RAII `CallbackLease`. The kernel callback is gated, so no packets can
be accepted while runtime gates are closed. A TX queue's teardown closes the
admission gate before releasing the queue. Host tests now include callback
close/drain ordering, concurrent close and reentrant manager transitions.

**An empty in-flight counter is not proof of Skywalk callback quiescence.**
Kernel-side proof that callbacks cannot run again after backend destruction,
plus full TX completion/RX packet ownership semantics, are still required.
Do not enable `ITLWM_AWDL_DATAPATH_LIVE` or AWDL registration.

See [STAGE4_2_SAFETY_REVIEW.md](STAGE4_2_SAFETY_REVIEW.md) for test commands,
open risks and the implementation boundary. This branch needs new local
macOS Tahoe builds and checks before it can be considered validated.


## Stage 4.3 — packet ownership simulation (host-only)

An isolated C++14 header, `AirportItlwm/AirportItlwmAWDLPacketFlow.hpp`,
models atomic batch claims, TX/RX packet ownership, exactly-once finalize,
explicit return acknowledgement and generation-stamped tokens. This is a
**test model**, not the actual Skywalk TX/RX implementation; no driver
source includes it or changes any runtime gate.

`verify_datapath.py` now runs `test_packet_flow.cpp` alongside the
Stage 4.2 tests. Details and the remaining 25G332 kernel-behavior questions
are in [STAGE4_3_PACKET_FLOW_REVIEW.md](STAGE4_3_PACKET_FLOW_REVIEW.md).
